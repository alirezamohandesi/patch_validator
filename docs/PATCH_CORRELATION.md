# PATCH CORRELATION

پیوند دادن خطای مشاهده‌شده به تغییرات واقعی کد — بخش اصلی پروژه (۲۵ نمره از ۱۰۰).

## مسئله

وقتی ابزار خطایی می‌بیند، باید بگوید **آیا این خطا به چیزی که وصله تغییر داده مربوط
است یا نه**. سند رسمی سه قید سخت می‌گذارد:

1. «محل Crash لزوماً روی خطوط تغییرکرده نیست.»
2. «باید امکان ارتباط غیرمستقیم از طریق Caller، Callee یا مسیر اجرا در نظر گرفته شود.»
3. «همجواری ظاهری خطا و Diff برای اثبات ارتباط کافی نیست.»
4. «در صورت نبود شواهد کافی، مقدار ارتباط را UNKNOWN قرار بده.»

به همین دلیل خروجی یک بله/خیر نیست، بلکه **درجه‌بندی‌شده** است.

## چهار سطح

| سطح | شرط | confidence | منتسب به وصله؟ |
|-----|------|------------|-----------------|
| `CONFIRMED` | فریمی از stack trace دقیقاً روی خطی است که وصله تغییر داده | `high` | بله |
| `LIKELY` | فریمی داخل تابعی است که وصله تغییر داده، ولی نه روی خط تغییریافته | `medium` | بله |
| `WEAK` | فقط فایل مشترک است | `low` | **خیر** |
| `UNKNOWN` | فریمی نیست، یا هیچ اشتراکی پیدا نشد | `none` | **خیر** |

`WEAK` و `UNKNOWN` یافته را حذف نمی‌کنند؛ یافته با همان برچسب در گزارش می‌ماند و اجرا
را به سمت عدم قطعیت می‌برد، نه به سمت یک ادعای مطمئن.

## الگوریتم

```
برای هر فریمِ هدف در stack trace (از درونی‌ترین به بیرونی‌ترین):
    1. آیا فایل این فریم در diff هست؟
       نه → UNKNOWN برای این فریم
    2. سمت درست diff را انتخاب کن:
       خطای روی base   → سمت «قدیم»
       خطای روی patched → سمت «جدید»
    3. آیا شمارهٔ خط این فریم جزو خطوط تغییریافتهٔ آن سمت است؟
       بله → CONFIRMED
    4. تابع دربرگیرندهٔ این خط را در منبعِ همان revision پیدا کن.
       آیا آن تابع با خطوط تغییریافته هم‌پوشانی دارد؟
       بله → LIKELY
    5. در غیر این صورت → WEAK

قوی‌ترین نتیجه میان همهٔ فریم‌ها برنده است.
اگر فریم برنده، فریم صفر نباشد → indirect = true
```

نکتهٔ کلیدی گام ۵: چون **همهٔ** فریم‌ها بررسی می‌شوند، ارتباط از طریق caller به‌صورت
طبیعی پیدا می‌شود و نیازی به منطق جداگانه ندارد.

## چرا سمت قدیم و جدید جدا هستند

خطایی که روی base دیده می‌شود، شماره‌خط‌های **فایل قبل از وصله** را دارد. همان خطا روی
patched، شماره‌خط‌های **فایل بعد از وصله** را دارد. اگر این دو را یکی بگیریم، هر همبستگی
به اندازهٔ طول وصله اشتباه می‌شود.

```
@@ -27,6 +27,12 @@ static int handle_text(...)
```

این hunk شش خط اضافه می‌کند. خط ۳۰ در فایل قدیم و خط ۳۰ در فایل جدید دو چیز متفاوت‌اند.

## نقطهٔ درج: مسئلهٔ وصله‌های صرفاً افزایشی

یک وصله که فقط خط **اضافه** می‌کند، هیچ خطی را حذف نمی‌کند. پس در سمت قدیم، مجموعهٔ
«خطوط حذف‌شده» خالی است — و بدون کار اضافه، **هیچ خطایی روی base هرگز به چنین وصله‌ای
مرتبط نمی‌شد**.

این باگ در عمل دیده شد: `incomplete-patch` که فقط یک نگهبان اضافه می‌کند، ابتدا برای
خطای `vuln_text_long` روی base نتیجهٔ `WEAK` می‌داد.

**راه‌حل:** هر hunk علاوه بر خطوط حذف‌شده و افزوده‌شده، «نقطهٔ درج» را هم ثبت می‌کند —
شمارهٔ خط قدیمی‌ای که خطوط افزوده پیش از آن قرار گرفته‌اند — و متقارناً «نقطهٔ حذف» را
در سمت جدید.

پس از این اصلاح، همان مورد `CONFIRMED` با `indirect: true` شد.

## نگاشت خط به تابع

`cfunctions.py` بدون parser کامل C کار می‌کند:

1. محتوای توضیحات و رشته‌ها با فاصله جایگزین می‌شود — طول و خطوط حفظ می‌شوند، پس
   شماره‌خط‌ها معتبر می‌مانند و آکولاد داخل رشته شمرده نمی‌شود.
2. عمق آکولاد پیمایش می‌شود. هر گذار از عمق ۰ به ۱ یک تعریف محتمل است.
3. نام از متن declarator پیش از آکولاد استخراج می‌شود.
4. کلمات کلیدی (`if`, `for`, `while`, …)، ماکروهای تابع‌مانند و آغازگرهای struct رد
   می‌شوند.

مواردی که به‌درستی مدیریت می‌شوند و در تست تثبیت شده‌اند: امضای چندخطی، آکولاد داخل
رشته و توضیح، `#define WRAP(x) do { … } while (0)`، و
`static const struct cfg DEFAULTS = { .a = 1 };`.

**در صورت شکست**، تابع شناسایی نمی‌شود و همبستگی به `WEAK` تنزل می‌کند. هرگز نام تابع
اشتباهی اختراع نمی‌شود.

## نمونه‌های واقعی

### ۱. ارتباط غیرمستقیم روی یک CVE واقعی

هدف `cjson`، وصلهٔ بالادست `3ef4e4e`:

```
FIXED  security_object_truncated_after_comma  corr=LIKELY  parse_object()  indirect=True

base   : HEAP_BUFFER_OVERFLOW detected by address_sanitizer at cJSON.c:787
why    : frame #1: the fault is inside parse_object() (lines 1607-1717),
         which the patch modified, but not on a changed line
         the relationship is indirect: the fault surfaced in parse_string
         at cJSON.c:787, which is reached from the changed code
```

خطا در `parse_string` رخ داده — تابعی که وصله **اصلاً دست نزده**. ابزار با پیمایش
فریم بالاتر، `parse_object` را پیدا کرده. بدون منطق ارتباط غیرمستقیم، این یافته
`UNKNOWN` می‌شد.

### ۲. تفکیک وصلهٔ ناقص

هدف `recparse`، وصلهٔ `incomplete-patch` که فقط `handle_text` را اصلاح می‌کند:

| یافته | ورودی | همبستگی | تفسیر |
|-------|-------|----------|-------|
| `FIXED` | `vuln_text_long` | `CONFIRMED` غیرمستقیم، `handle_text()` | خطا در `copy_payload:21` بود؛ caller آن `handle_text:30` دقیقاً خط تغییریافته است |
| `INCOMPLETE_FIX` | `vuln_raw_long` | `WEAK`، `copy_payload()` | مسیر RAW فقط فایل مشترک دارد — این وصله هرگز آن را لمس نکرده |

ردیف دوم نشان می‌دهد چرا `WEAK` نباید «منتسب» حساب شود: آسیب‌پذیری باقی‌مانده واقعاً
ربطی به این وصله ندارد، و گزارش دقیقاً همین را می‌گوید.

### ۳. نبود شواهد

```
FIXED  vuln_text_long (release)  corr=UNKNOWN

notes: no symbolised stack frames were captured for this fault, so no
       relationship to the diff can be established
       detected by fortify_source, which reports that a violation occurred
       but not where
```

`_FORTIFY_SOURCE` فقط می‌گوید یک کران نقض شد. ابزار حدس نمی‌زند.

## گزارش همبستگی

هر یافتهٔ امنیتی یک `Correlation` کامل دارد:

| فیلد | محتوا |
|------|-------|
| `finding_id` | شناسهٔ یافته |
| `correlation_status` | `CONFIRMED` / `LIKELY` / `WEAK` / `UNKNOWN` |
| `confidence` | `high` / `medium` / `low` / `none` |
| `affected_file`, `affected_function` | محل مرتبط |
| `relevant_diff_hunk`, `relevant_diff_hunk_text` | hunk دقیق به‌همراه متنش |
| `matched_frame_index`, `indirect` | کدام فریم و آیا غیرمستقیم است |
| `stack_trace_evidence` | همهٔ فریم‌های هدف |
| `correlation_evidence` | دلیل هر فریم، به زبان انسانی |
| `frame_matches` | نتیجهٔ تفصیلی هر فریم |
| `base_behavior`, `patched_behavior` | رفتار دو نسخه |
| `notes` | هشدارهای تفسیری |
| `evidence_refs` | مسیر فایل‌های شاهد |

## آنچه انجام نمی‌شود

- **تحلیل جریان داده.** اگر نقص از طریق ساختاری که جای دیگری خراب شده منتقل شود و در
  stack trace ردی نگذارد، پیدا نمی‌شود.
- **تطبیق معنایی diff.** ابزار نمی‌فهمد وصله *چه کاری* می‌کند، فقط *کجا* را تغییر داده.
- **حدس زدن.** نبود شواهد به `UNKNOWN` ترجمه می‌شود، نه به «احتمالاً مرتبط».
